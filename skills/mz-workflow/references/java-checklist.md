# Java / Spring 设计与实施检查清单

在阶段 3（方案设计）、阶段 5（任务拆解）、阶段 6（实施）和阶段 7（收尾）逐项核对；只写适用的项，不适用的说明原因。

## 1. 构建与运行环境

- [ ] `mvn -v` / `./gradlew -v` 的实际 JDK 与 `pom.xml` 的 `java.version` / Gradle 的 toolchain 一致（本机可能同时装了 1.8 和 17，按项目要求设置 `JAVA_HOME`）
- [ ] 父 POM 可从本地缓存或项目配置的 Maven 仓库解析（`~/.m2/settings.xml` 的 mirror 是否可用）
- [ ] 模块构建命令明确：Maven `mvn -q -pl <module> -am test`，Gradle `./gradlew :<module>:test`
- [ ] 打包方式（jar/war）与部署方式一致
- [ ] 是否有代码生成（MyBatis Generator、Lombok、MapStruct）需要先跑

## 2. 分层与包结构

- [ ] Controller 只做参数校验和编排，不写业务逻辑
- [ ] Service 接口与实现分离是否符合项目惯例
- [ ] DTO / VO / Entity / PO 的边界；不要直接把 Entity 暴露给前端
- [ ] 异常体系：业务异常 vs 系统异常；全局异常处理是否覆盖
- [ ] 返回值统一包装（如 `Result<T>`）是否沿用

## 3. 事务与并发

- [ ] `@Transactional` 的传播行为、`rollbackFor`、`readOnly` 是否正确
- [ ] 同类内部方法调用导致事务/AOP 失效（self-invocation）
- [ ] 事务内不要做远程调用、发 MQ、发邮件等长耗时操作
- [ ] 幂等：唯一键、去重表、状态机、Token 机制
- [ ] 并发：乐观锁（version）、悲观锁（`SELECT ... FOR UPDATE`）、分布式锁的粒度与超时
- [ ] 定时任务多实例重复执行（ShedLock / Quartz 集群 / 分布式锁）
- [ ] 异步线程池的拒绝策略、上下文传递（TraceId、登录态）

## 4. 数据与 SQL

- [ ] 表结构变更：DDL、索引、默认值、历史数据迁移
- [ ] 大表分页避免深分页；`LIMIT`/`ROWNUM` 写法符合数据库类型
- [ ] N+1 查询；批量操作是否用 `foreach` / batch
- [ ] 事务隔离级别与脏读/幻读风险
- [ ] 敏感字段加密/脱敏；SQL 注入（优先参数绑定）
- [ ] 软删除、多租户、数据权限是否影响查询条件

## 5. 接口与兼容性

- [ ] URL、方法、参数、返回值的向后兼容
- [ ] 新增必填参数/枚举值对老客户端的影响
- [ ] 版本化策略（URL 版本 / Header 版本）
- [ ] 限流、熔断、超时、重试（Feign / RestTemplate / WebClient）
- [ ] 文件上传大小、导出内存占用

## 6. Spring 细节

- [ ] Bean 生命周期、循环依赖、`@Conditional` 条件装配
- [ ] AOP 代理陷阱（`this` 调用、final 方法、private 方法）
- [ ] `@Async` 的线程池与异常处理
- [ ] 缓存：key 设计、过期、击穿/穿透/雪崩、更新一致性
- [ ] 配置项：新增配置是否有默认值、是否纳入配置中心
- [ ] 启动顺序、健康检查、优雅停机

## 7. 消息与外部依赖

- [ ] MQ 消息幂等、重试、死信、顺序性
- [ ] 本地事务与消息发送的一致性（事务消息 / Outbox）
- [ ] 第三方接口的超时、降级、重试退避
- [ ] 回调/通知的验签与防重放

## 8. 可观测与运维

- [ ] 关键路径日志（入参摘要、耗时、结果），避免打印敏感信息
- [ ] TraceId / SpanId 透传
- [ ] 指标：成功/失败计数、耗时、积压
- [ ] 告警：失败率、延迟、积压阈值
- [ ] 回滚方案：开关、配置、数据回滚

## 9. 安全

- [ ] 认证与鉴权（接口权限、数据权限）
- [ ] 输入校验（长度、格式、枚举、文件类型）
- [ ] 越权（水平/垂直）、ID 枚举
- [ ] 敏感信息不落日志、不返回前端
- [ ] 反序列化、SSRF、路径穿越（如涉及）

## 10. 测试

- [ ] 单元测试：JUnit 5 + Mockito；覆盖核心分支和边界
- [ ] 集成测试：`@SpringBootTest` / `@MybatisTest`；必要时 Testcontainers
- [ ] 每个任务先写失败测试，确认 RED 原因正确，再写实现
- [ ] 全量测试，不只跑被改的文件；已有失败要按名称报告
- [ ] 构建命令与 CI 一致
