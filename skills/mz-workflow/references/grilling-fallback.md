# grilling 内置降级协议

当 `grilling` 技能不可用时使用。协议来自 mattpocock/skills 的 `grilling` 技能（MIT），此处保留核心行为。

## 核心模型

把需求想成一棵**决策树**：每个决策会分支出依赖它的后续决策。

- **前沿（frontier）**：所有前置决策已经确定、现在就能问的问题。
- **按轮次提问**：一轮问完整个前沿，每题编号并给出你的推荐答案，然后等用户回答。
- 依赖本轮未决问题的问题，放到下一轮，不要提前问。
- 措辞要让用户回答"是"就等于接受你的推荐答案。

## 每轮格式

```markdown
❓ **Q1** - **<问题标题>**：<问题正文，可含多个选项>

➡️ <你的推荐答案>

---

❓ **Q2** - **<问题标题>**：<问题正文>

➡️ <你的推荐答案>
```

## 事实与决策

- **事实是 agent 的事**：需要查代码、配置、依赖、日志时，派子代理去查，不要问用户。
- **决策是用户的事**：每个决策都要明确问，并等回答。
- 不要因为查事实阻塞整轮；只把依赖该事实的问题放到下一轮。

## 结束条件

1. 前沿为空：每条分支都走过，没有未说出口的假设。
2. 用户明确确认"达成共识"。

未确认前不要进入方案设计或写代码。

## 常见失败模式

- 模型自问自答：不要替用户做决定。
- 跳过确认直接开始实现：Gate 1 必须停。
- 问题太多太碎：按轮次问，不要一次问一个问四十轮。
- 把可以查的事实拿去问用户：先查再问。
